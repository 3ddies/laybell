# Laybell 1.1.5 — release notes

Supersedes **1.1.4** (live on both stores). Pure JS/TS (no new native module), plus one
**additive** SQL column. Built from `feature/subject-lift-stickers`.

## What's New (store-facing)

- A cleaner **Explore** — a bold editorial layout and a redesigned Laybell TV hero.
- **Privacy controls** — hide your like and save counts, and turn off comments, per post or
  account-wide.
- **Shops look sharper on your profile** — show your open shop as a cover rail of listings or
  a simple button.
- **Storybooks** now sit right beside your name and bio.
- **Polished album pages** that pick up the color of your cover art.
- Performance and stability improvements.

## What's in it (since 1.1.4)

- `feat(explore)` — editorial grid as the sole layout (switcher retired); Laybell-TV hero
  rework (title/description, grow-from-tile open transition).
- `feat(privacy)` — hide like/save counts + turn off comments (IG-style), per-post overrides
  + account defaults, enforced server-side. *(ships with 1.1.4's client already; `post_privacy.sql`
  already live.)*
- `feat(shop)` — seller chooses how their open shop appears on their profile (button vs cover
  rail) via `profiles.shop_display`.
- `feat(profile)` — storybooks moved beside name/bio (compact shelf); shop rail preview.
- `feat(album)` — cover-color accent on the Play button + artist row + livelier track rows.

## OWNER RUNBOOK (the steps the assistant can't run — prod + stores)

```powershell
# 1) Deploy the one additive column (safe: app treats a missing column as 'button')
npx supabase db query --linked -f supabase/sql/profile_shop_display.sql

# 2) Schema drift gate — should return NO rows (the .sql was generated by schema-audit.mjs).
#    If it returns rows, deploy the supabase/sql/<file> each one names (e.g. post_privacy.sql
#    for the privacy feature) via `db query --linked -f`, then re-run until it's empty.
npx supabase db query --linked -f scripts/.schema-audit.sql

# 3) Builds (production profile; EAS auto-increments build number / version code)
eas build -p ios --profile production
eas build -p android --profile production

# 4) Submit once builds finish (ASC key + Play service account are wired in eas.json)
eas submit -p ios --profile production --latest      # -> App Store Connect
eas submit -p android --profile production --latest  # -> Play production (draft)
```

- **iOS:** after `eas submit`, in App Store Connect create the **1.1.5** version, select the
  build, paste the What's New above, keep reviewer notes, **Submit for Review**. No new IAPs.
- **Android:** `eas submit` uploads a **draft** to the production track → in Play Console add the
  `<en-US>` What's New and send for review (managed publishing per your setting).
- After it's live: bump §0.0 of `docs/LAUNCH_CHECKLIST.md` to 1.1.5.
